# Отдел продаж: маршрутизация

Главная сессия играет приёмную отдела. Агенты вызывать друг друга не могут — цепочку
ведёшь ты. Роли лежат в `.claude/agents/`, устройство отдела — в `otdel-prodazh/README.md`.

## Перед началом

```bash
python3 tools/catalog.py stats     # индекс на месте и не пустой
```

Индекс пересобирается сам, когда страницы каталога новее его, — следить за этим не нужно.
Первый запуск после обновления витрины занимает несколько секунд.

## Пришло обращение клиента

1. **Диспетчер** (агент `dispetcher`) — передай ему текст обращения дословно, вместе с
   каналом, откуда оно пришло. Он заведёт сделку и вернёт `D-ГГГГММДД-NNN`, список
   уточняющих вопросов и направление.
2. **Эксперт** по названному направлению — передай ему номер сделки и всё, что известно
   об объекте. Он пройдёт свой опросный лист (`otdel-prodazh/oprosnye-listy.md`), вернёт
   2–3 варианта и запишет подбор.
   Направлений два и больше → вызови обоих экспертов, сделка остаётся одна.
3. **Расчётчик** (агент `raschetchik`) — только когда в ответе появляются суммы.
4. **Ответ клиенту** собери сам из выдач экспертов. Отправляет человек.

Экспертов одного шага, если их несколько, вызывай **одним сообщением** — они не зависят
друг от друга и отработают параллельно.

## Клиент ответил, сделка двинулась

```bash
python3 tools/ledger.py show --deal D-…                       # что уже известно
python3 tools/ledger.py zametka --deal D-… --by <кто> --text "…"
python3 tools/ledger.py stage --deal D-… --to торг
python3 tools/ledger.py stage --deal D-… --to проигран --why "дороже конкурента на 40 тыс"
```

Причина при закрытии обязательна. Разбор проигрышей — половина пользы отчёта.

## Спросили про продажи

Вызови агента `nachalnik-otdela-prodazh`. Отчёт, просьбы и предложения собирает он и
кладёт в `otdel-prodazh/otchety/`. Сам сводку не пиши: тогда цифры разойдутся с журналом.

## Быстрые ответы без всей цепочки

Вопрос «есть ли такая модель и сколько стоит» — отвечается напрямую, без агентов:

```bash
python3 tools/catalog.py find --q "MSAF-09HRN8"
python3 tools/catalog.py show bytovye:DTXS-09K3XA41A
```

Но сделку всё равно заведи: обращение, которого нет в журнале, не попадёт ни в конверсию,
ни в отчёт.

## Правила, которые не обходятся

1. Цена, наличие и ТТХ — только из `catalog.py`. Ни одного значения по памяти.
2. Нет подходящего в каталоге — это `ledger.py probel`, а не «примерно похожее».
3. Наценку к цене каталога второй раз не применяют: там уже цена клиенту.
4. Всё, что решает владелец, идёт через `ledger.py vopros`, а не остаётся в переписке.
5. Ответ клиенту отправляет человек.
